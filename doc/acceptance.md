# 验收标准 — New API 多租户代理分销平台(三期)

> **文档定位**:本项目**唯一权威验收基准**。三期(一期 完整可上线运营 / 二期 装修·合规·计费硬化 / 三期 品牌营销升级)的验收要求、**通用技术标准门**、具体技术要求,全部收敛于此。
> **口径(已与用户确认)**:① 三期**对齐当前执行现实**;② 每条验收项**双轨**——「功能判据(可演示)」+「技术判据(可量化工程门)」;③ **一期 = 完整可上线运营**(含 new-api 基座 + 真实支付 + 正式上线 + 管理端/代理自助后台,可真实收款);代理品牌装修、内容合规(违禁词)与计费硬化在二期。
> **维护规则**:验收项只增不删。

## 文档说明

**验收项编号**:`P{期}-{域}-{序号}`,序号**按域在本期内顺序**编。如 `P1-TP-05`(一期·套餐·第5项)、`P2-BILL-01`(二期·计费·第1项)。
**关联门**:`#1`–`#12` 指向 Part 0 的通用技术门。
**状态图例**:`✅达成`(功能+技术双轨均过)｜`🟡部分`(逻辑/纵切达成,本期内待收口)｜`⏳进行`｜`⬜未启动`。
**双轨结构**:每条验收项统一给出
- **功能判据(演示)**:演示账号 + 操作步骤 + 预期可见结果 —— 对外可演示、非工程人员可判定。
- **技术判据(工程门)**:可量化的工程门槛(覆盖率/`-race`/隔离用例/并发不击穿/幂等/迁移回滚…),引用 `#N` 门。
- **证据 / 关联门 / 状态**。

# Part 0 · 验收技术标准总则(三期通用)

> 所有期、所有验收项的**技术判据**都从这 12 道门取标准。新增/改造代码先过门,再谈功能验收。

## 0.2 门禁·大白话版(给非技术同学 / 外部验收看)

> 下表用大白话解释 12 道门——不懂技术也能看明白每道门**在防什么**、**不做会怎样**。技术口径(阈值/命令)见 0.1。

| # | 门 | 它保证什么(大白话) | 不做会怎样 |
| --- | --- | --- | --- |
| #1 | 代码质量 | 交货前自检:能编译运行、格式整齐、没低级错、多人同时操作不打架 | 程序跑不起来,或偶发崩溃 |
| #2 | 测试覆盖 | 每个核心功能都有自动化测试替你试过;算钱的代码每种情况都验到 | 改一处坏一片,上线才发现 |
| #3 | 依赖倒置 | 模块像积木靠"插头"连接、不焊死,能单独替换、单独测试 | 改一处牵动全身,没法独立验证 |
| #4 | 多租户隔离 | 每个代理只能看/改自己的数据,绝对看不到同行的用户、账单、订单、统计 | 数据串户泄露——严重事故 |
| #5 | 并发一致性 | 再多人同时扣款也不超卖:钱包不透支、套餐不超月限额 | 被并发刷爆,平台真金白银亏损 |
| #6 | 幂等 | 同一笔支付/开通/入账,哪怕收到好几次通知,也只算一次 | 一笔充值入账两次——资损或纠纷 |
| #7 | 错误码 | 出错时有统一编号和清楚说明,一眼知道是哪儿、什么原因 | 出问题排查半天,客服也说不清 |
| #8 | 集成/E2E | 上线前在独立仿真环境用真数据库/真模型跑通,绝不拿正式服务器做实验 | 拿真实用户当小白鼠,出事波及现网 |
| #9 | 迁移 | 改数据库表都配套"升级脚本 + 回退脚本",出问题能一键还原 | 表改坏了,数据回不去 |
| #10 | 安全 | 密钥只放服务器不进代码库;上传只收指定文件类型;支付通知先验真伪 | 密钥泄露被盗用 / 收到假支付通知放货 |
| #11 | 部署 | 一条命令起停;测试与正式环境互不影响;新版先放小流量,不对就撤回 | 上线即翻车且无法回退,全员停摆 |
| #12 | 演示 | 每条关键功能都能用演示账号当面演给你看,关键的配截图/录屏 | 说"做好了"却拿不出实证,无法验收 |

## 0.3 门禁详述(关键三门)

**#4 多租户隔离门(安全红线)**:不仅 `scopeByTenant` 注入,必须有**否定测试**——租户 A 的 Token 访问租户 B 的用户/日志/订阅/统计**必被拒**(`FORBIDDEN_TENANT`/404);管理员接口与代理接口分离鉴权。任何新增租户维度表/端点,验收必须附对应越权用例,否则不通过。

**#5 并发一致性门(资损红线)**:钱包扣减 `balance - cost >= 0`、套餐计量 `used_usd + cost <= month_limit`,均以**条件 UPDATE 受影响行数=0 判失败**实现。验收必须有 ≥500 goroutine 并发测试,断言零穿透,`go test -race` 无数据竞争。当前 tokenplan 已达成(500 goroutine 不击穿)。

**#6 幂等门(资损红线)**:`order_no` 唯一约束做幂等键;重复回调短路返回成功且**不二次入账/不二次激活/不二次分润**。验收必须有"同订单二次回调"用例。

# Part 5 · 项目方阶段验收清单(甲方视角 · 大白话)

> Parts 1–4 是给研发的"怎么做、怎么测";本节是给**项目方/出资方**的"每期你要验收什么"——不懂技术也能照着签字。每期统一四问:**能看到什么 / 收到什么 / 怎么验 / 通过标准**。

## 5.1 一期验收 ——「完整可上线、可真实收款、可运营」

> 一句话定位:**做完一期就能正式开站、真实收款,管理员能运营、代理能自助、终端能用**。这是面向真实用户的可上线产品(中小额套餐先行)。

**① 能看到什么(现场/录屏演示)**
- 真实注册/登录(非演示账号);管理员真实把用户设为代理。
- 多租户:`tokendream.wedreamhub.com` 独立品牌站;未开通域名提示;`*.wedreamhub.com` 通配 + HTTPS 正常。
- **真实调用计费 + 双桶差异(核心卖点)**:套餐用户走"套餐桶"(月额度封顶)、按量用户走"钱包桶"(余额扣减),独立互不影响。
- **真实支付**:微信/支付宝真实付款 → 真实开通套餐 / 真实充值到账;**重复支付不会重复到账**。
- tokenplan 6 档购买生成 30 天订阅;用满/到期拦截重购;Trial 再买被拒(防刷)。
- **管理后台可运营**:管理员管套餐(增删改)、管子代理(设类型/成本/分润)、审提现;**代理能自助**管我的用户组/用户/推广渠道/兑换码、自助上架改套餐价。
- 隔离:代理只看自己,越权 403;上线小流量灰度无事故。

**② 收到什么(交付物)**
- 演示账号 + 主流程 + 管理/代理自助演示步骤脚本。
- 一期接口文档;正式栈部署 + 备份/回滚 + 监控告警说明。
- 测试报告(覆盖率 ~98.7%、并发不击穿、E2E)。
- **真实支付对账报告** + 灰度 24h「无资损 / 无越权」报告。
- stub→真实 替换核对清单(逐项确认已替真)。

**③ 怎么验**:用真实小额付款走一遍"充值 / 买套餐",确认到账且代理收益正确;在后台真实操作(建套餐/设代理/审提现),代理端自助建推广/兑换码;跟演示脚本走主流程;查灰度与对账报告。

**④ 通过标准(签字)**:**能真实收款且账目正确**;管理端 + 代理自助后台可独立操作;演示版(dev-login/stub 支付/自签证书)全部替真;通配 + HTTPS 合规;灰度 24h 零资损零越权;3 标杆(真实计费/套餐封顶/双桶并发)+ 真实支付亲眼可见。
> ⚠️ **上线范围**:完整多档风控在二期——一期建议**先开放中小额套餐(Trial/Mini/Solo)**。完整 breakage 监控已移出 1–3 范围,**Pro/Max 大额套餐建议长期下架或人工管控**(防巨亏)。
> ⚠️ **代理品牌装修(自定义美化)在二期**:一期代理可换主题色 + 配基础站点信息,但完整的可视化装修编辑器在二期。

## 5.2 二期验收 ——「装修 + 内容合规 + 防滥用硬化」

> 一句话定位:**代理能自助美化品牌站,平台能屏蔽违禁内容,计费防住欠费与刷量**。

**① 能看到什么**
- 代理**自助品牌装修**:品牌 tabs(品牌/联系/充值/内容/首页/协议)可视化配置,主题色限色板(基础 OEM 雏形;营销化/多模板留三期)。
- **违禁词屏蔽**:用户发含违禁词的消息 → 被拦截并收到提醒("消息含违禁内容");**管理员后台能看到谁、什么时间、命中了什么词**。
- 计费硬化:高额请求**预扣防欠费**;**真实多档风控**(限频/并发/IP 指纹 + Trial 三维限购);满额分级告警。

**② 收到什么(交付物)**:代理装修操作手册;违禁词库 + 命中记录说明;风控规则说明;预扣 + 风控测试报告。

**③ 怎么验**:代理端自助配出一套品牌装修并生效;**发一条含违禁词的消息,确认被拦截 + 提醒,且管理员后台能看到该命中记录**;模拟高额与异常请求,看预扣与风控正确拦截、正常请求不误杀。

**④ 通过标准(签字)**:代理可自助完成品牌装修;**违禁词屏蔽生效且管理员可见命中记录**;预扣 + 多档风控生效且不误杀;Trial 三维限购口径(D2)已锁;可据此放开更多套餐档位。

## 5.3 三期验收 ——「品牌营销升级」

> 一句话定位:**购买页营销化 + 代理可用自己的域名**。锦上添花项,可按需排期。

**① 能看到什么**
- 营销化购买页(原价划线 / 折扣角标 / 推荐热门 / 套餐对比)+ 主站/代理多套模板。
- OEM 代理**自定义域名 + 独立 HTTPS**;证书到期自动提醒。

**② 收到什么(交付物)**:营销页 + 模板说明;OEM 域名接入与证书配置手册。

**③ 怎么验**:看营销页还原度;实际访问 OEM 自定义域名(HTTPS 正常、到期提醒可见)。

**④ 通过标准(签字)**:营销化前端 + OEM 自定义域名/SSL 可用。
> ⚠️ **不在 1–3 范围**:完整风控引擎、财务报表 + breakage 监控、续订自动化 / 多语言 / 多币种 / 移动端已移出(按需另立项)。因此 **Pro/Max 大额套餐建议长期下架或人工管控**(防巨亏)。

> **给项目方的总提醒**:平台商业模型依赖 breakage(用户通常只用到月限额约 1%),所以"防刷限购 + 满额监控 + 月限额可下调"是底线能力——**一期上线即带 user 维限购 + 真实支付,务必先放中小额套餐**;二期补全多档风控(三维限购/RPM/IP)。⚠️ **完整 breakage 监控 / 财务报表已移出 1–3 范围**,故 **Pro/Max 大额套餐建议长期保持下架或人工管控**,并始终保留主站"月限额可随时下调"开关(否则一旦被刷满,满额上游成本 ≈售价 20 倍,巨亏)。
