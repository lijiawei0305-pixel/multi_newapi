📝 Executive Summary / 总体评估

📋 审计结论

项目概况：newapi628 是以 Go、Gin、GORM 为核心的多供应商 AI API 网关，覆盖 SQLite、MySQL、PostgreSQL、Redis、认证、计费、多租户、Default/Classic/Orbit Web 与 Electron。本轮从原始 8 个发现出发，由 3 个子 Agent 分域修复，再按 Fuck My Shit Mountain full 模式复审 25 个维度。

结论：整体提升为 9.2 / S。修复已提交到 PR #4；MySQL 8.2/8.4.10 真实矩阵均通过。Cloudflare R2 的 30 天前缀锁已确认，最新远端密文完成 SHA 校验、age 解密、MySQL 8.4 导入、Redis RDB→AOF、隔离应用 readiness/version 和 15 项只读账务对账。演练还发现并修复了 TTL key 自然过期被误判为恢复损坏的问题。当前没有已知仓库内可执行 bug，剩余 1 个外部 Medium。

主要成果：依赖/Go/secret/SA* 归零；超大模块清零；Node/Actions、Gitee、Electron 与镜像治理 fail closed；双版本恢复与真实远端恢复有运行证据；恢复 manifest 新增永久 Redis key 不变量并兼容旧备份。

边界：没有部署或原地升级生产应用/数据库；所有恢复仅在唯一命名的远端隔离 containers、volumes 与 internal network 中执行并已删除。未运行真实签名发版、人工无障碍旅程或生产负载测试。

Resolved F01. 远端不可变副本端到端恢复证明已完成

Historical: HighStatus: Resolved
📁 Category: Stability / Data Integrity / Release📌 Status: Resolved 2026-07-22📍 Affected area: Cloudflare R2 and isolated disaster recovery
Evidence： deploy/ops/README.md:86-88,106 — 明确说明对象锁/跨账号保留和真实远端恢复属于外部证明。 deploy/ops/offsite-copy.sh:2-12,101-120 — 支持 fail-closed 异地复制、manifest 与 SHA 回执。 Cloudflare 控制台只读证据 — production/newapi_test/ 有启用中的 30 天 Bucket Lock，35 天生命周期规则晚于锁定期。 运行证据 — 最新 encrypted SHA 全量复验；本地 mode 600 age identity 与 recipient 匹配；密文解密后 manifest/三个内容 SHA 通过。远端唯一隔离项目恢复到 MySQL 8.4.10 与 Redis 8.8，应用 readiness/version 通过，15 项账务 reconcile 全部 PASS；所有隔离资源和解密临时目录随后删除，生产 healthcheck 全绿。
Problem：已解决。演练过程中额外发现 TTL key 会依据 RDB 绝对过期时间自然减少，原来的“总 key 数精确相等”会误拒绝健康恢复。
Why it matters：修复后以永久 key 精确守恒为稳定不变量，同时允许 TTL key 随时间减少；既不会误报，也不会放过永久 Trial/风控状态丢失。
Realistic failure scenario：本次真实演练复现了 3 个快照 key 中 2 个 TTL key 正常到期、仅加载 1 个永久 key 的情况，旧逻辑会错误中止恢复。
Implemented fix
新 manifest 记录 redis_persistent_keys；恢复端要求永久 key 精确守恒，总 key 只能因 TTL 到期减少，RDB→AOF 与正式重启过程不得增加总数或改变永久数；旧 manifest 使用兼容上界检查。
Long-term control
按月重复同一远端对象解密恢复，归档对象 key、SHA、RTO/RPO、readiness、reconcile 和 Bucket Lock 截图/API 证据。
Regression test：ops orchestration fixture 固定覆盖 snapshot keys=3、loaded=1、persistent=1；双版本真实 restore matrix 继续验证完整恢复。
Actual effort：约 1.5 小时，包括真实演练发现与代码修复。
Principle restored：Recoverability is proven across the encrypted remote-object boundary.
